# OmegaForge Studio 界面设计规范

## 一、设计语言

界面采用深色工作台风格：低噪声、高信息密度，面向工程场景。

| 维度 | 取値 |
|---|---|
| 风格 | 深色工作台，信息优先，不使用装饰性动效 |
| 底色 | 深灰蓝渐层，按界面层级分三级深度 |
| 主色 | 品牌紫（主操作、强调） |
| 语义色 | 成功绿、警示黄、失败红，仅用于状态表达 |
| 字体 | 系统界面字体；代码、日志、用量数字使用等宽字体 |
| 圆角 | 卡片较大圆角，控件较小圆角，状态标签用全圆角 |
| 动效 | 仅两处：按钮悬停抬升、运行中脉冲提示 |

## 二、设计令牌

界面颜色与间距**不在代码中写死**，统一由设计令牌生成：

```
design/tokens.json        # 单一事实源（OKLCH 色彩空间）
        │
        │  构建脚本生成
        ▼
frontend/src/styles/tokens.css
```

令牌分两层：

- **基础层**：色板按用途分组（表面层级 0–12、品牌、成功、警示、失败等），采用感知均匀的色彩空间，保证同层级间的视觉差异一致。
- **语义层**：按界面角色命名（背景、前景、卡片、主色、次要、弱化、强调、危险等），引用基础层。

界面代码只使用语义层名称，不直接引用色板。修改配色只需改动令牌文件后重新生成，无需逐个组件调整。

## 三、技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | React + TypeScript | 类型安全，组件可复用 |
| 构建 | Vite | 开发热更新，产物按需分包 |
| 样式 | Tailwind + 设计令牌 | 令牌驱动，样式不散落 |
| 组件 | Radix 基础组件 | 键盘操作与读屏支持开箱可用 |
| 图标 | 图标字体库 | 线性图标，风格统一 |

## 四、信息架构

界面按"输入与过程在左、输出与结论在右"组织，职责单向流动：

```
┌──────────────┬────────────────────────┐
│  输入与过程   │      输出与结论         │
│              │                        │
│  素材投喂     │  对比结论              │
│  进度与日志   │  基因构成              │
│              │  编译产物              │
└──────────────┴────────────────────────┘
```

十个面板通过统一的侧边导航切换：

| 面板 | 内容 |
|---|---|
| 蒸馏 | 素材输入、参数、启动、实时进度与日志 |
| 竞技场 | 对比结论与判定依据 |
| 基因组 | 基因构成与调整 |
| 运行记录 | 任务列表、详情、日志回放 |
| 对话 | 与提炼产物直接对话 |
| 知识库 | 词条管理与检索 |
| 待办 | 任务清单 |
| 技能与人设 | 技能安装、人设查看 |
| 用量 | 各阶段用量与耗时统计 |
| 设置 | 服务商、权限、偏好 |

## 五、交互流程（以蒸馏为例）

1. 用户填入素材与参数，点击开始
2. 按钮转为不可重复点击状态，日志区开始滚动
3. 界面按固定间隔获取最新进度，增量追加日志
4. 任务完成后，结论区、基因区、产物区一次性呈现
5. 失败时保留已产生的日志，并说明失败原因

状态：空闲 → 已提交 → 进行中 → 已完成 / 已失败。全程防止重复提交。

## 六、数据呈现原则

- **结论优先**：对比结果用大号等宽数字呈现，胜/平/负三色区分。
- **进度可见**：任务全过程按阶段显示进度，界面上不出现进度回退。
- **日志原样**：流水线日志用等宽字体逐条呈现，便于核对。
- **空态引导**：每个区块在无数据时给出下一步操作提示，而不是空白。
- **数字统一**：所有数量类数字使用同一套千分位格式，不同面板保持一致。

## 七、可访问性与适配

- 输入控件均绑定语义化标签，键盘可完整操作
- 焦点状态有明确描边，不依赖颜色单独区分
- 窄屏（≤960px）自动切换为单栏布局
- 用户内容一律以文本节点渲染，不做字符串拼接式注入
- 配色对比度满足正文阅读要求

## 八、与桌面外壳的关系

界面是纯前端工程，通过本地回环地址访问后端接口。桌面外壳（Tauri）负责：

- 应用启动时自动拉起后端服务
- 提供原生窗口、菜单与系统集成
- 打包为各平台安装包

同一份界面产物既可在浏览器中开发调试，也可由桌面外壳加载，**两者共用同一套代码与接口**，不存在两套界面实现。
